# 원본 아키텍처와 단계별 누적 구조 문서화

사용자 요청: tomcat-architecture.html 상단에는 원본 Tomcat, 바로 아래에는 각 단계가 완료되었을 때의 구조를 배치한다. 서버 기능 구현은 이번 범위가 아니다.

- 기존 원본 10.1.34 구조도·근거·용어 상세·일반/JSP 요청 재생을 보존한다.
- 0~7단계를 세로로 배치하고 누적 흐름·조립 관계·추가 요소·차이·검증 기준·근거 문서를 함께 표시한다.
- README와 0~2단계 학습 기록 기준 실제 구현은 2단계까지다. 3~7단계는 예정 목표로 표시하고 실행 결과를 만들지 않는다. 초기 로드맵의 과거 상태 기록은 보존한다.
- 원본 메서드·호출·상태·오류·소유권·종료 및 차이 표는 기존 고정 소스 지도, 학습 문서, 단계 계획으로 연결한다. 미조사 정책은 확정하지 않는다.
- 문서 검증: 기존 브라우저 검사로 재생·용어 설명·오프라인·모바일 동작을 확인하고 단계 순서·상태·링크·화면 배치를 확인한다. 서버 clean verify·HTTP 재실험·완료 커밋·학습 태그 생성은 서버 구현 단계에 적용하며 이번 문서 편집에는 수행하지 않는다.

## 문서 검증 결과 — 2026-11-06

- Microsoft Edge headless에서 기존 architecture-check.cjs의 7개 검사 통과: 38개 용어 상세, 키보드 포커스, 일반/JSP 재생, 모바일 터치, 로컬 HTML 직접 열기.
- 별도 브라우저 검사로 원본 → 단계별 구조 순서, 8개 단계 상태, 중복 ID 없음, 문서 내 로컬 링크 존재, 390px 화면에서 전체 단계의 가로 넘침 없음을 확인했다.
- 데스크톱·모바일 화면을 캡처해 확인했다. 원본 재생 제어는 원본 섹션 안에 두어 단계별 구조를 읽을 때 화면을 가리지 않게 한다.
- 서버 테스트 53개 등의 문구는 기존 단계 실행 기록을 인용한다. 이번에는 HTML 문서 브라우저 검사만 실행했다.

## 사용자 후속 요청 — 원본과 같은 그림으로 변경

- 텍스트 상자의 가로 나열을 제거하고 0~7단계마다 독립적인 인라인 SVG 구조도를 넣었다. 원본과 같은 중첩 박스·요청 실선·응답 점선·Mapper 조회선을 사용한다.
- 0단계는 빌드 기반, 1단계는 단일 Endpoint, 2단계는 Protocol 조립과 HTTP 분리, 3단계는 고정 Wrapper, 4단계부터 컨테이너 중첩, 5단계는 FilterChain, 6단계는 Server·Service·Connector 및 작업 풀, 7단계는 SimpleTomcat과 사용자 디스패처를 그린다.
- 구성 및 책임 범위와 호출 경로를 구별하고, Mapper에서 Wrapper 직접 호출선은 그리지 않는다. 종료 순서는 별도 주석으로 표시한다. 예정 단계와 실제 실행 기록의 구분은 유지한다.
- 8개 SVG 렌더링·라벨 영역·모바일 가로 스크롤·페이지 오류 없음 확인. 데스크톱 캡처를 직접 검토했고 기존 브라우저 검사 7개도 통과했다. 서버 구현 및 검증 상태는 변경하지 않았다.
