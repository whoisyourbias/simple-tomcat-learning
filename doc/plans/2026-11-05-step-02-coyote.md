# 2단계 · Coyote와 HTTP 처리

상태는 예정이다. 기준 Tomcat 태그는 10.1.34다.

## 이전 문제와 최소 해결

한 클래스에 Host 검사 하나는 쉽게 추가할 수 있다. 요청 행·버전·헤더·응답 규칙이 늘어나면 소켓 종료 코드와 섞이고 HTTP 문법 테스트에도 서버를 띄우게 된다. 규칙 추가 자체와 책임 분리의 이유를 구별한다.

## 개념·인터페이스·작업

Endpoint는 소켓과 최종 close를 소유하고 Handler에 처리만 위임한다. `Http11Protocol`이 Endpoint·Processor·Adapter를 조립한다. `Http11Processor.process(InputStream, OutputStream)`로 소켓 없이 HTTP를 검증한다.

Coyote `Request`는 method·원래 requestURI·queryString·protocol·헤더를 제공한다. `Response`는 status·헤더·UTF-8 본문을 담는다. `Adapter.service(Request, Response)`가 응답 내용을 제공한다. `ProtocolHandler`는 실행·종료 계약을 제공한다.

추가할 위치는 util/net/Endpoint, coyote의 네 계약·데이터 타입, coyote/http11의 Protocol·Processor다. 이전 동작 테스트를 남기고 HTTP 단위 테스트를 먼저 작성한다.

## Tomcat 구현 근거와 핵심 대응

[AbstractProtocol.ConnectionHandler.process](https://github.com/apache/tomcat/blob/10.1.34/java/org/apache/coyote/AbstractProtocol.java), [Http11Processor.service/prepareRequest/prepareResponse](https://github.com/apache/tomcat/blob/10.1.34/java/org/apache/coyote/http11/Http11Processor.java), [NioEndpoint.SocketProcessor](https://github.com/apache/tomcat/blob/10.1.34/java/org/apache/tomcat/util/net/NioEndpoint.java)를 대조한다.

| 핵심 동작 | Tomcat 동작 | 프로젝트 예정 흐름 | 테스트 |
|---|---|---|---|
| 조립·연결 정리 | Handler가 Processor를 확보·호출, Endpoint가 소켓 상태 처리 | Protocol → Endpoint → Processor → Adapter | 실제 연결·오류 후 다음 요청 |
| HTTP 경계 | Processor가 요청 준비 후 Adapter 호출·응답 작성 | 스트림 → Request → Adapter → Response → 전송 | 독립 파싱·UTF-8·상태별 본문 |

## 완료 테스트

- 정상 요청의 메서드·URI·query·헤더 전달, HTTP/1.0·1.1을 확인한다. 본문 없는 유효 메서드를 GET만으로 제한하지 않는다.
- malformed 400, 지원 외 버전 505, 유효한 본문 요구 미지원 501, 일반 Adapter 예외 500과 다음 정상 요청을 확인한다.
- UTF-8 바이트 Content-Length, HEAD·204·205·304 본문 처리를 확인한다.
- 파싱 실패와 Adapter 실패를 구별하고 출력 실패 후 잘못된 재응답을 시도하지 않는지 확인한다.
- 기존 연결 종료·서버 종료 테스트와 실제 TCP HTTP 왕복을 유지한다.

## 구현 순서·실행

테스트 실패 확인 → HTTP 분리 → 관련 테스트 → clean verify → 실제 HTTP 실험 → 차이·제약 문서 갱신 → 완료 커밋·learn/step-02 순서다.

예정 실행은 `java -cp target/classes simpletomcat.coyote.http11.Http11Protocol 18081`이다. 정상 curl 요청과 `curl --http1.1 -H 'Host:' --max-time 3 -i http://localhost:18081/hello`를 비교한다. 현재 구현·실행 결과는 없다.

## 차이와 생략

| 항목 | 실제 Tomcat·근거 | 예정 동작 | 이유 | 영향·제약 | 검증 | 후속 |
|---|---|---|---|---|---|---|
| 프로토콜 | 위 Processor의 keep-alive·본문 필터 | 본문 없는 요청·연결당 한 건 | 프레이밍 범위 제한 | 연결 재사용·업로드 없음 | 종료·거부 테스트 | 유지 |
| 본문 오류 | 정상 본문 처리 가능 | 유효 본문 요구는 501 | 프로젝트 범위 정책 | Tomcat과 다른 501 의미 | malformed와 구별 | 유지·차이 기록 |
| 오류 진입 | 오류 상태에 따라 Adapter 오류 경로 호출 가능 | 파싱 오류는 자체 응답 | 최소 오류 경로 | 오류 페이지·로깅 경로 차이 | 상태·호출 횟수 | 유지 |
| 문법 허용 | InputBuffer의 다양한 허용 분기 | 엄격한 최소 문법 | 과도한 호환성 구현 제한 | 일부 유효 요청 거부 가능 | 입력별 근거 표 | 구현 전 세부 조사 |

헤더 제한·입력 문법·오류 상태의 상세 정책은 구현 전 해당 소스 분기를 확인해 표에 추가한다. 확인하지 못한 동작을 Tomcat 정책으로 확정하지 않는다. [공통 범위](../reference/02-scope-and-differences.md)가 적용된다.
