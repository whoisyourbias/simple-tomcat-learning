# 1단계 · 요청 하나를 처리하는 서버

상태는 예정이다. 기준 Tomcat 태그는 10.1.34다.

## 이전 문제와 최소 해결

0단계에는 빌드 환경만 있다. TCP 연결을 수락한 뒤 언제 응답하고 무엇을 닫아야 두 번째 요청을 받을 수 있을까? 먼저 한 클래스에서 accept·헤더 끝 읽기·고정 응답을 구현한다. 응답 후 서버까지 닫는 경우와 요청 연결만 닫는 경우를 비교한다.

## 익힐 개념과 인터페이스

TCP는 바이트 스트림이며 read 경계와 상대의 write 경계가 일치하지 않는다. 헤더 끝 CRLF 두 번, 응답의 바이트 길이, EOF, 연결·서버 수명과 자원 소유권을 익힌다.

예정 구현은 `simpletomcat.util.net.Endpoint(int port)`의 `getPort()`, `serve()`, `close()`다. 생성 시 바인딩하고 0이면 임시 포트를 사용한다. serve를 실행하는 스레드와 종료를 요청하는 스레드를 구별한다.

## Tomcat 구현 근거와 핵심 대응

[Acceptor.run](https://github.com/apache/tomcat/blob/10.1.34/java/org/apache/tomcat/util/net/Acceptor.java)은 연결을 수락해 Endpoint로 인계하고 실패한 연결을 정리한다. HTTP 해석은 하지 않는다.

| 핵심 동작 | Tomcat 동작 | 프로젝트 예정 흐름 | 테스트 |
|---|---|---|---|
| 연결 수락·소유권 | Acceptor 수락·인계, Endpoint 측 연결 정리 | accept → 현재 연결 등록 → 헤더 읽기 → 고정 응답 → 연결 close → 다음 accept | 두 연결·EOF·종료·포트 반환 |

## 구현 작업과 완료 기준

1. EndpointTest에 아래 시나리오를 작성해 미구현으로 실패함을 확인한다.
2. Endpoint 한 클래스와 main을 구현한다. 아직 Processor·Adapter를 만들지 않는다.
3. close가 수신 소켓과 읽기 중 연결을 닫아 대기를 해제하게 한다. 등록·종료 경합에서 새 연결을 놓치지 않게 한다.
4. 단계 학습 문서·현재 상태·차이를 갱신하고 전체 검증 후 완료 커밋과 learn/step-01을 남긴다.

- 같은 서버에서 두 요청에 상태 200·고정 본문·올바른 UTF-8 Content-Length를 받는다.
- 분할된 헤더 끝을 완성하기 전에는 응답하지 않고 완성 후 응답한다.
- 헤더 미완성 EOF이면 응답 없이 닫고 다음 연결에 응답한다.
- accept·헤더 읽기 중 close로 작업이 유한 시간 안에 끝난다. 반복 close·포트 재바인딩도 확인한다.

## 실행 계획

구현 후 clean verify를 실행한다. `java -cp target/classes simpletomcat.util.net.Endpoint 18081`을 시작하고 별도 터미널에서 `curl --max-time 3 -i http://localhost:18081/hello`를 두 번 보낸다. Windows에서는 curl.exe를 사용한다. Ctrl+C로 종료한 뒤 포트 반환을 확인한다. 현재 실행 결과는 없다.

## 차이와 생략

| 항목 | 실제 Tomcat·근거 | 예정 동작 | 이유 | 영향·제약 | 검증 | 후속 |
|---|---|---|---|---|---|---|
| 책임 | Acceptor와 Processor 분리 | Endpoint에 HTTP 고정 응답 포함 | 분리 전 모델 | 올바른 HTTP인지 검사하지 않음 | 잘못된 요청도 고정 응답 | 2단계에서 해소 |
| EOF·오류 | 파서·상태별 처리 | 미완성 EOF 무응답, 연결 IOException 뒤 다음 연결 | 파서 이전 모델 | 오류 응답 상세 없음 | EOF 뒤 정상 요청 | 2단계 정책으로 교체 |
| 실행 | NIO 기반 인계 | 블로킹 순차 | 연결 수명에 집중 | 느린 연결이 다음 요청 지연 | 읽기 대기·종료 | 동시성은 6단계, NIO는 설명 |

다음 문제는 Host 없는 HTTP/1.1 요청도 같은 응답을 받는다는 점이다. HTTP 규칙을 소켓 없이 검증할 경계를 만든다. [2단계](2026-11-05-step-02-coyote.md)로 이어진다.
