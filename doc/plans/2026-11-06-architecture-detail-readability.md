# 원본 아키텍처 용어 상세의 정합성·가독성 수정

사용자가 앞선 검토의 오류 1건과 가독성 개선점 3건 수정을 요청했다. 대상은 `doc/00-overview/tomcat-architecture.html`이며 서버 구현 단계 변경은 아니다. 기존 원본 그림·단계별 구조·요청 재생과 과거 검증 기록을 보존한다.

## 수정 순서와 판단 기준

- [x] MapperListener 설명을 고정 소스의 실제 이벤트 메서드로 정정한다.
- [x] 모듈 설명의 대표 구현 안내를 본문 앞에 배치한다.
- [x] 구성요소는 짧은 클래스명·쉬운 실행 흐름·정리를 먼저 보여주고, 전체 패키지·조립 관계·실제 호출식·소스는 펼쳐 읽게 한다. 기술 정보는 삭제하지 않는다.
- [x] 개념·예시는 정의·관련 대상·관계·사용 예만 보여준다. 공통 초기화·종료 안내를 제거한다.
- [x] 기존 브라우저 검사, 38개 용어의 데스크톱·모바일 표시, 펼치기와 키보드 조작, 소스 링크·오프라인 동작을 확인하고 실제 결과를 기록한다.

## 고정 소스와 설명 대응

근거: [Tomcat 10.1.34 MapperListener](https://github.com/apache/tomcat/blob/10.1.34/java/org/apache/catalina/mapper/MapperListener.java).

`MapperListener`는 `ContainerListener`, `LifecycleListener`를 구현하며 `propertyChange()`는 없다. `StandardService`가 생성·보유하며 생성자로 Service와 Mapper 참조를 확보한다. `startInternal()`은 리스너 연결과 등록을 수행한다. `containerEvent()`는 자식·별칭·서블릿 매핑·welcome file 변경에 반응하고, `lifecycleEvent()`는 시작·중지 시점의 등록·해제에 반응한다. 이벤트별로 Mapper 등록·제거 메서드를 호출하며 모든 이벤트가 같은 register 메서드를 통과하지는 않는다. `stopInternal()`은 리스너를 제거한다. 이는 배포·구성 이벤트 경로이며 요청 실행·HTTP 오류 응답을 직접 처리하는 경로가 아니다. 확장 모듈의 미조사 오류·종료 정책은 기존 조사 항목을 유지한다.

| 항목 | 실제 동작 | 자료의 수정 동작 | 이유·영향 | 검증 | 후속 |
|---|---|---|---|---|---|
| MapperListener 이벤트 | containerEvent/lifecycleEvent에서 이벤트별 등록·제거 | 존재하지 않는 propertyChange 표기를 제거하고 두 이벤트 책임 구분 | 없는 메서드를 찾거나 모든 변경이 같은 등록 경로라고 오해하지 않도록 정정 | 고정 소스와 표시 문구 대조 | 전체 이벤트 정책 확대는 별도 조사 |
| 모듈과 대표 구현 | Coyote·Catalina·Jasper는 단일 객체가 아님 | 대표 구현명을 포함한 범위 안내를 요약 다음에 표시 | 대표 클래스의 수명을 모듈 전체의 수명으로 해석하는 혼동 감소 | 세 패널의 안내 순서 확인 | 모듈 전체 생명주기 조사 완료로 표시하지 않음 |
| 긴 기술 정보 | 원본 클래스명·메서드·상태는 유지되어야 함 | 간단한 흐름과 정리는 먼저 표시하고 전체 근거를 details로 제공 | 첫 화면 밀도 감소, 정확한 기술 정보는 펼쳐 읽어야 함 | 펼친 뒤 원문·링크 보존 및 키보드·모바일 검사 | 추가 정책 변경 없음 |
| 개념·예시 | ROOT·localhost 등은 독립 Tomcat 인스턴스가 아님 | 일반적인 생성·종료 안내를 없애고 관련 대상·관계·사용 예 표시 | 의미 없는 반복 제거 | 개념 패널에서 초기화·종료 공통 항목 부재 확인 | 구체 자원 정책은 해당 구성요소 참조 |

이번에는 문서 UI만 변경한다. Java 서버의 clean verify·HTTP 실험·완료 커밋·학습 태그는 새로 수행하거나 생성하지 않는다.

아래 결과는 2026-11-06에 문서 UI를 대상으로 실행했다. 서버 학습 단계의 새 구현 완료를 뜻하지 않는다.

| 검사 | 실제 결과 | 범위·제약 |

| 별도 임시 Playwright 검사 | 1440px·390px·320px에서 각각 38개 패널 확인 | 구성요소의 접힘 기본값, Enter로 펼치기·Space로 접기, Escape의 원래 용어 포커스 복귀 확인 |
| 정합성과 정보 보존 | 통과 | 수정 전 복사본과 구조화 데이터를 비교. MapperListener의 정정 문구·소스 메서드 표기와 개념의 공통 안내 제거를 제외하고 기존 요약·클래스·관계·조립·호출·정리·소스 데이터를 보존. 펼친 패널의 전체 클래스명과 소스 URL도 확인 |
| 모듈·개념 구분 | 통과 | 세 모듈의 대표 구현 안내가 클래스·실행 설명보다 앞에 위치. 개념에는 기술 상세 접기와 공통 초기화·종료 항목이 없음 |
| 가로 넘침 | 1440px·390px에서 없음 | 320px에서는 기존 요청 단계 버튼 등 패널 외부에 문서 가로 넘침이 이미 존재함. 이번 상세 패널은 화면 안에 있으며 펼쳐도 문서 너비를 늘리지 않음. 320px 문서 전체 개선은 이번 범위에서 제외 |
| 화면 확인 | 데스크톱·390px 모바일 캡처 확인 | 기본 Endpoint 패널 높이: 390px에서 약 2,103px → 871px. localhost는 774px → 454px. 기술 상세는 별도 펼침이며 이 수치는 기본 패널만 비교 |
| 브라우저 오류·외부 다운로드 | 없음 | 별도 검사에서 JavaScript 오류와 HTTP(S) 리소스 요청 0건. 소스 링크는 클릭하지 않음 |
| 변경 공백 검사 | `git diff --check` 통과 | 기존 수정 내용을 보존하고 이번 HTML 변경만 수정 전 복사본과 추가 비교 |

기존 검사 실행에는 번들 Node 패키지 경로를 `NODE_PATH`로 지정했다. 별도 검사는 임시 폴더에서 수행했으며 프로젝트에 테스트 의존성이나 신규 테스트 파일을 추가하지 않았다. 과거 검증 기록과 공개 학습 태그는 변경하지 않았다.
