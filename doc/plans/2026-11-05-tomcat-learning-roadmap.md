**5단계 구현 후 (2026-11-10):** 0~5단계 구현·전체159사례·clean verify·JAR HTTP 검증. [5단계 실행 기록](../05-filter/01-filter-chain.md) 참고. 6~7단계는 예정이며 아래 이전 시점 요약은 보존한다.

## 목표와 설계 원칙

준비 이후 필수 구현은 7단계로 고정한다. 소규모 버그 수정이나 세부 규칙마다 단계를 추가하지 않는다. 범위 변경이 필요하면 이유·완료 기준·기존 단계 영향을 문서에 먼저 기록한다.

각 단계는 이전 서버의 한계 → 최소 해결 시도 → 책임 분리 → 실제 요청·테스트 → Tomcat 소스 대조 순서다. 클래스 이름만 맞추는 것을 완료 기준으로 삼지 않는다. 외부 응답이 같은 리팩터링은 테스트 격리·소유권·변경 범위 개선을 증명하고 기존 동작을 보존하면 학습 단계로 인정한다.

1단계의 단일 서버와 3단계의 고정 Wrapper 호출은 중간 모델이다. 각각 2·4단계에서 책임 결합을 해소한다. 4단계에서 기본 Pipeline을 만들고 5단계에서 사용자 Valve와 Filter를 추가한다.

## Tomcat 구현 근거

기준은 **Apache Tomcat 10.1.34 릴리스 태그**다. [공식 소스 지도](../reference/01-tomcat-source-map.md)에 고정 링크·메서드·확인할 동작을 기록한다. S1~S9의 핵심 요청·생명주기 흐름을 계획의 기준으로 삼는다. 공개 API 전체와 오류 분기를 모두 조사 완료한 것으로 간주하지 않는다.

단계 구현에 착수하기 전에 해당 소스의 책임·순서·상태·오류·소유권·종료를 확인한다. 아직 확정하지 않은 입력·예외·설정 정책은 해당 단계의 조사 항목에 남긴다. 핵심 근거가 불분명하면 그 부분의 구현 준비를 완료로 표시하지 않는다.

## 핵심 동작 대응과 구현 단계

|---|---|---|---|---|
| 0 | 실행 기반 없음 | JDK·컴파일·테스트 환경 | Maven Wrapper → JUnit → JAR | [준비 절차](../reference/03-learning-workflow.md) |

| 2 | HTTP와 소켓 책임 결합 | AbstractProtocol·Http11Processor.service의 준비·Adapter 호출 | Endpoint → Processor → Adapter → 응답 | [독립 파싱·오류·UTF-8](2026-11-05-step-02-coyote.md) |
| 3 | 인스턴스 관리 혼재 | StandardWrapper.allocate/unload | Adapter → 고정 Wrapper → Servlet | [실제 HTTP로 1/2/1](2026-11-05-step-03-servlet.md) |

## 차이와 생략

[공통 차이 표](../reference/02-scope-and-differences.md)는 실제 Tomcat 동작·이번 범위·이유·영향·검증·후속 여부를 기록한다. 단계별 차이 표는 해당 단계에 적용되는 구체적인 중간 모델과 정책을 기록한다.

JDK 21·블로킹 소켓·본문 없는 HTTP/1.0·1.1·연결당 한 요청·자체 최소 Servlet 계약·프로그램 등록을 사용한다. NIO 내부 구현·표준 API 전체·배포·로더 격리·세션·인증·Jasper·운영 확장은 설명 자료로 학습한다. 외부 simple-spring 주문 저장 연동은 필수 완료 조건에 포함하지 않는다.

HTTP 오류 코드·입력 거부·예외 처리·종료 정책은 프로젝트 선택과 Tomcat 대응을 구별한다. 종료 제한 시간을 넘겨 실행 중인 서블릿을 정상 해제했다고 기록하지 않는다.

## 문서화와 구현 작업

각 단계의 코드 구현 시 doc/01-socket/부터 doc/07-embedded/까지 학습 문서를 만든다. 이전 한계·최소 해결·책임 분리 이유·변경 전후 흐름·실행·실제 차이·다음 문제를 포함한다. 현재 상태와 구현 제약을 함께 갱신하고 과거 실행 날짜·결과를 보존한다.

README에는 처음 공부하는 순서·선수 지식·준비 절차·고정 단계표·실제 실행 명령·생성된 태그·제외 범위를 안내한다. 아직 존재하지 않는 실행 클래스나 태그를 현재 사용 가능한 것으로 설명하지 않는다.

## 커밋·검증·완주

현재 초기 커밋은 문서만 담는다. 준비 단계 완료 후 learn/step-00, 구현 단계 완료 후 learn/step-01~07을 만든다. 완료 커밋은 코드·테스트·학습 문서가 함께 빌드되는 지점이다. 공개 태그는 이동하지 않는다.

관련 테스트와 전체 clean verify, 실제 HTTP 요청을 각 단계에서 확인한다. 네트워크는 임의 포트·유한 대기·명시적 동기화·자원 정리를 사용한다. 모든 테스트 메서드에 한국어 입력·기대 결과 주석을 붙인다. 마지막에 0~7태그를 각각 별도 체크아웃해 빌드한다.

7단계의 두 업무 경로·404/500 복구·동시 요청·종료·JAR 실행·제외 범위 설명을 충족하면 필수 과정을 완료한다. 이후 기능은 별도 계획으로만 진행한다.
