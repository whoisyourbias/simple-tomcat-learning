03 · Service 소유 Mapper가 실제로 하는 일

Mapper는 HTTP를 파싱하거나 서블릿을 실행하는 객체가 아닙니다. 배포·설정 시 매핑 테이블을 유지하고 요청마다 어느 Host / Context / Wrapper를 사용할지 조회합니다. Tomcat 10.1.34의 StandardService가 Mapper와 MapperListener 인스턴스를 보유합니다. 따라서 여러 Connector가 같은 Service에 연결되어 있다면 같은 매핑 정보를 참조할 수 있습니다.

① 시작·배포·변경 시

MapperListener가 등록 정보 동기화

Engine 아래의 Host, Context, Wrapper에 대한 시작·중지 및 구성 변경 이벤트를 관찰하고, 사용 가능한 매핑 정보를 Mapper에 등록하거나 제거합니다.

  • Host 이름·별칭·기본 Host
  • Context 경로·웹 앱 버전·welcome file
  • Wrapper의 서블릿 URL 패턴 (/, *.jsp 등)
② HTTP 요청 도착 시

CoyoteAdapter가 Mapper 조회

HTTP Processor가 요청을 해석한 뒤, Adapter가 필요한 URI 처리와 Catalina 요청·응답 객체 연결을 수행하고 Service의 Mapper에 조회를 요청합니다.

  • Host 이름으로 가상 Host 선택
  • 요청 URI에서 웹 앱 Context 선택
  • 서블릿 매핑 규칙으로 Wrapper 선택
③ 조회가 끝난 후

MappingData를 사용해 Pipeline 실행

Mapper는 대상 객체를 직접 호출하지 않고 요청의 MappingData에 선택 정보를 채웁니다. Adapter는 Engine Pipeline을 호출합니다. Engine·Host·Context의 기본 Valve는 선택된 다음 컨테이너로 전달하고, Wrapper의 기본 Valve는 FilterChain을 실행합니다.

  • Engine → Host → Context → Wrapper
  • Wrapper Valve → FilterChain → Servlet
  • 그 다음에야 Spring MVC가 Controller를 선택
// CoyoteAdapter의 핵심 순서를 요약한 코드 (Tomcat 10.1.34) connector.getService().getMapper() .map(serverName, decodedURI, version, request.getMappingData()); // 성공적으로 후처리되면 Adapter가 Engine의 Pipeline을 호출 connector.getService().getContainer() .getPipeline().getFirst().invoke(request, response);

현재 요청의 매핑 결과

상단의 요청 종류를 바꾸면 이 예시도 함께 갱신됩니다. MappingData는 반환 객체를 새로 만드는 방식이 아니라, 전달받은 객체에 결과를 채우는 방식입니다.

05 · Tomcat이 책임지는 것
네트워크 연결, HTTP 처리, 웹 애플리케이션·서블릿 선택, 서블릿 생명주기, 필터 호출, 동시 요청 실행과 응답 전송을 담당합니다.
서블릿은 보통 여러 요청에서 공유됩니다. 요청별 데이터는 지역 변수나 요청 객체에 보관하고, 공유 상태에는 동시성 처리가 필요합니다.
06 · 두 프로젝트의 연결 지점
simple-tomcat이 요청·응답 객체와 서블릿 호출 계약을 제공하고, simple-spring이 그 계약에 맞는 디스패처를 등록합니다.
학습용 첫 버전에서는 Host와 Context를 각각 하나로 고정해 시작할 수 있습니다. 이후 다중 애플리케이션을 구현하면서 계층을 확장합니다.
Tomcat의 Context는 웹 애플리케이션 단위입니다. Spring의 ApplicationContext는 빈을 관리하는 IoC 컨테이너입니다.


Jasper는 JSP를 서블릿으로 변환·컴파일하는 JSP 엔진입니다. 그림의 *.jsp 분기는 JSP 요청이 매핑되는 경우를 보여 줍니다. MapperListener는 배포·변경 시 매핑 정보를 갱신하며 Mapper는 요청 시 MappingData를 채웁니다. 요청 종류를 선택해 DispatcherServlet 경로와 직접 JSP 경로를 각각 재생할 수 있습니다. Jasper 공식 문서 · Tomcat 모듈 목록 · Tomcat 요청 처리 흐름
Spring MVC 요청과 직접 JSP 요청을 비교하는 동기 처리 개념도입니다. 필터가 응답을 바로 반환하는 경로와 비동기 처리는 생략했습니다. ROOT Context에 디스패처가 /로 매핑된 예시이며, simple-spring의 디스패처 이름과 API는 구현 과정에서 정할 수 있습니다.
